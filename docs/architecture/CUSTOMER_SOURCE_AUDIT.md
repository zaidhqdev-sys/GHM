# Customer Source Audit

**Status:** SOURCE AUDIT — RECONCILED / CONSTRUCTION AUTHORIZED

**Source product:** QuoteFlow (`zaidhqdev-sys/QuoteFlow`, `main`)

## 1. Purpose

Establish the source-of-truth contract for QuoteFlow's Customer capability before constructing the dependent GHM Quote capability.

This audit authorizes construction of a canonical GHM Customer resource. It does not authorize production migration or cutover.

## 2. Production source model

QuoteFlow currently persists Customers through account-scoped application storage.

The storage key is `quoteflow.customers.v1` and is resolved through the account-scoped storage boundary. Customer data is therefore not global application data. fileciteturn50file0

When an active organization exists, QuoteFlow scopes persistence to that organization; otherwise it falls back to authenticated-user scope. This is the same account-storage boundary used by Quotes.

## 3. Canonical Customer fields

QuoteFlow defines Customer as:

- `id: string`
- `name: string`
- `phone: string | null`
- `email: string | null`
- `createdAt: string`
- `status: 'active' | 'archived'`

The persisted validator requires those exact shapes. fileciteturn50file0

## 4. Ownership boundary

Customer is an account/organization-owned CRM contact.

It is **not**:

- a GHM authenticated account identity;
- a Business membership;
- a Project owner;
- a QuoteFlow Item;
- a marketplace Business;
- a global person identity.

A Customer may be represented by a real-world person or organization, but the current product source does not establish a global identity or authentication relationship.

Therefore GHM must not make `customer.account_id` point to the Customer itself or reinterpret Customer as `ghm.account_identity`.

`ghm.customer.account_id` identifies the owning account/organization. `ghm.customer.id` identifies the account's CRM Customer record.

## 5. Creation

QuoteFlow exposes Customer creation with:

- name;
- phone nullable;
- email nullable.

Creation assigns a generated Customer ID, current timestamp, and `active` status. fileciteturn51file0

Commercial entitlement limits may restrict creation in the current product. That limit is a product/commercial concern and is not itself a Customer data-model invariant. GHM Customer must not hard-code QuoteFlow's current free-plan customer count.

## 6. Lifecycle

The only Customer lifecycle states evidenced are:

```text
active
archived
```

Customer creation always starts `active`.

The product supports:

- archive active Customer → archived;
- restore archived Customer → active.

No hard-delete operation is exposed by the current Customer context. fileciteturn51file0

GHM therefore must preserve Customer rows and use lifecycle state rather than deletion for this first capability.

## 7. Mutation boundary

The current source exposes only these Customer mutations:

1. create Customer;
2. archive Customer;
3. restore Customer.

There is no qualified Customer edit operation for name, phone, or email in the current source.

Therefore the initial GHM Customer operation contract must not expose arbitrary Customer update.

## 8. Quote dependency

Quote creation requires a selected Customer and only active Customers are selectable. Quote creation snapshots the Customer's name, phone, and email into the Quote. This establishes Customer as a real dependent resource rather than merely a denormalized Quote field.

The Customer record remains independently addressable after Quote creation.

Customer archival must therefore not erase Quote history.

## 9. Identity and IDs

QuoteFlow currently uses locally generated string IDs. GHM uses canonical relational numeric identifiers for GHM-owned resources.

GHM Customer IDs will therefore be GHM-owned `bigint` identifiers. A future adapter may maintain an external QuoteFlow ID mapping during migration, but no provider-specific ID column belongs in the canonical Customer schema.

## 10. Canonical GHM model

The canonical GHM relation is:

`ghm.customer`

Minimum fields:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `account_id bigint NOT NULL REFERENCES ghm.account_identity(id)`
- `name text NOT NULL`
- `phone text`
- `email text`
- `status text NOT NULL DEFAULT 'active'`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

No global uniqueness on name, phone, or email is authorized by the source.

## 11. Customer access semantics

A non-admin authenticated context may access only Customers owned by its account/organization.

The Customer resource must not use role `customer` to mean ownership of a Customer row. GHM's authenticated role and resource ownership are separate concerns.

Admin access follows the existing GHM administrative boundary.

## 12. Quote relationship

`ghm.quote.customer_id` will reference `ghm.customer(id)`.

The FK must use `ON DELETE RESTRICT` or equivalent durable-history behavior. Customer hard deletion is not part of the initial lifecycle, and Quote history must not disappear because of Customer lifecycle changes.

New Quote creation must require Customer status `active`.

Existing Quotes remain valid when their Customer becomes archived.

## 13. Explicit exclusions

This audit does not authorize:

- global person identity;
- authentication for Customers;
- Customer-to-account identity merging;
- arbitrary Customer editing;
- Customer hard delete;
- contact deduplication by email/phone;
- marketing consent state;
- CRM pipeline state;
- Customer notes;
- invoice/customer-accounting semantics;
- provider-specific migration IDs;
- production data movement;
- production cutover.

## 14. Construction authorization

The source is sufficient to construct the minimum provider-neutral GHM Customer capability.

The implementation must remain limited to the documented create/archive/restore/read boundary and must establish least-privilege runtime access before Quote implementation proceeds.

## 15. Production safety

QuoteFlow remains on its existing production persistence during GHM construction. No production environment, credentials, routing, traffic, data, or storage migration is authorized by this audit.
