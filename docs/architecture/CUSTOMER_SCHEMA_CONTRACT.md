# GHM Customer Schema Contract

**Status:** CONSTRUCTION CONTRACT — SCHEMA DESIGN FROZEN

## 1. Purpose

Define the minimum provider-neutral PostgreSQL schema for the QuoteFlow Customer capability identified by the live product source audit.

This is a CRM Customer resource, not an authenticated account identity and not a marketplace Business.

## 2. Canonical relation

`ghm.customer`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `account_id bigint NOT NULL REFERENCES ghm.account_identity(id) ON DELETE CASCADE`
- `name text NOT NULL`
- `phone text`
- `email text`
- `status text NOT NULL DEFAULT 'active'`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

## 3. Ownership

Customer ownership is account/organization scoped.

`account_id` is the canonical GHM owner. It must not be replaced by Business membership or authenticated Customer role.

This follows the existing account-owned GHM resource pattern used by Project. fileciteturn53file0

## 4. Field invariants

### Name

Required. The implementation must reject blank/whitespace-only names.

The source does not establish a canonical maximum length. The canonical GHM schema therefore does not introduce an arbitrary maximum that could reject valid source data.

### Phone

Nullable text. No normalization or uniqueness rule is authorized by the source.

### Email

Nullable text. No normalization or uniqueness rule is authorized by the source.

### Status

Exactly:

```text
active
archived
```

No other lifecycle values are authorized.

## 5. Lifecycle

Create:

- status = `active`;
- generated GHM ID;
- generated creation/update timestamps.

Archive:

- `active` → `archived`.

Restore:

- `archived` → `active`.

No hard delete operation is authorized.

## 6. Historical behavior

Customer archival does not delete or invalidate existing Quote history.

A Quote may reference an archived Customer historically.

Only new Quote creation requires an active Customer.

## 7. Runtime privilege boundary

Runtime must have only the privileges required by the Customer operations.

Required direction:

- SELECT for authorized Customer reads;
- INSERT on `account_id`, `name`, `phone`, `email`;
- UPDATE only on `status` and required `updated_at` mutation support;
- sequence usage for identity generation.

Runtime must have no DELETE privilege.

Runtime must not receive blanket table DML.

## 8. Access boundary

Non-admin reads and lifecycle mutations must be constrained to the authenticated owner's `account_id`.

Admin access follows the existing GHM administrative boundary.

No role is treated as implicit ownership merely because it is named `customer` or `business`.

## 9. Indexes

Required initial indexes:

- `(account_id, created_at DESC)` for owner customer history;
- `(account_id, status, created_at DESC)` for active/archived retrieval.

No email/phone/name uniqueness or speculative search indexes are authorized.

## 10. Provider-neutral boundary

The schema must not contain:

- Supabase UUIDs;
- `auth.uid()`;
- RLS policies;
- AsyncStorage keys;
- QuoteFlow-specific IDs;
- provider-specific authentication identifiers.

## 11. Explicit exclusions

Not part of this first Customer capability:

- arbitrary Customer profile editing;
- hard delete;
- global identity resolution;
- contact deduplication;
- marketing consent;
- CRM pipeline state;
- customer notes;
- invoicing/accounting state;
- payment state;
- production migration;
- production cutover.

## 12. Dependency role

This resource is a prerequisite for the foreign-keyed Quote capability.

Once Customer is implemented and qualified, `ghm.quote.customer_id` may reference `ghm.customer(id)` with durable historical behavior.

## 13. Qualification gate

Customer cannot be marked qualified until evidence demonstrates:

1. account ownership enforcement;
2. create produces active Customer;
3. blank name rejection;
4. nullable phone/email behavior;
5. exact active/archived vocabulary;
6. archive behavior;
7. restore behavior;
8. no hard-delete path;
9. unauthorized account access denial;
10. Quote-compatible historical retention;
11. least-privilege runtime grants;
12. runtime DELETE denied;
13. repository/service tests pass;
14. runtime qualification passes;
15. existing GHM capability qualifications remain intact.
