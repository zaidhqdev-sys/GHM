# GHM Trust Schema Contract

**Status:** CONSTRUCTION CONTRACT — SCHEMA DESIGN FROZEN

## 1. Purpose

Define the provider-neutral PostgreSQL schema for the Trust score capability reconciled from the live Zaid Connect source audit.

This contract authorizes construction on the GHM construction branch only. It does not authorize production migration, Supabase changes, product adapters, shadow traffic, credential changes, or cutover.

## 2. Canonical relation

```text
ghm.trust_score
```

Canonical resource name: `trust_score` (singular GHM form of Connect `trust_scores`).

Each row stores the calculated Trust score for exactly one Business.

Exact physical definition:

```text
id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
business_id bigint NOT NULL REFERENCES ghm.business(id) ON DELETE CASCADE
profile_complete smallint NOT NULL DEFAULT 0 CHECK (0..15)
phone_verified smallint NOT NULL DEFAULT 0 CHECK (0..10)
email_verified smallint NOT NULL DEFAULT 0 CHECK (0..10)
id_verified smallint NOT NULL DEFAULT 0 CHECK (0..10)
cipc_verified smallint NOT NULL DEFAULT 0 CHECK (0..10)
vat_verified smallint NOT NULL DEFAULT 0 CHECK (0..5)
insurance_verified smallint NOT NULL DEFAULT 0 CHECK (0..15)
reviews_score smallint NOT NULL DEFAULT 0 CHECK (0..15)
completed_projects smallint NOT NULL DEFAULT 0 CHECK (0..10)
total_score smallint NOT NULL DEFAULT 0 CHECK (0..100)
trust_level text NOT NULL DEFAULT 'bronze'
  CHECK (trust_level IN ('bronze','silver','gold','platinum'))
last_updated timestamptz NOT NULL DEFAULT now()
created_at timestamptz NOT NULL DEFAULT now()
updated_at timestamptz NOT NULL DEFAULT now()
UNIQUE(business_id)
```

No Supabase UUID, `auth.uid()`, or RLS policy objects are part of the GHM schema.

## 4. Ownership and write authority

Trust rows are owned by the Business relationship (`business_id`), not by an account row.

Score mutation authority is **calculation-only** through:

```text
ghm.calculate_business_trust_score(p_account_id bigint, p_business_id bigint)
```

`p_account_id` must be the authenticated `AuthContext.userId` supplied by the service/repository. No caller-controlled session GUC is authorized.

## 5. Foreign keys

```text
ghm.trust_score.business_id -> ghm.business.id ON DELETE CASCADE
```

## 6. Indexes

```text
trust_score_level_total_idx ON ghm.trust_score (trust_level, total_score DESC)
trust_score_last_updated_idx ON ghm.trust_score (last_updated DESC)
```

## 7. Runtime privileges

```text
OWNER TO ghm_schema_owner
GRANT SELECT ON ghm.trust_score TO ghm_runtime
REVOKE INSERT, UPDATE, DELETE ON ghm.trust_score FROM ghm_runtime
GRANT EXECUTE ON ghm.calculate_business_trust_score(bigint, bigint) TO ghm_runtime
```

No blanket runtime DML. Sequence USAGE may be granted for identity catalog consistency; inserts occur only inside the SECURITY DEFINER calculate function.

## 8. Calculation input binding (GHM)

Formulas preserve Connect source exactly.

Available GHM Business input today:

- `ghm.business.rating` → `reviews_score`

Absent GHM Business columns (score as 0 until separately authorized Business profile extension):

- `description` → `profile_complete`
- `phone` → `phone_verified`
- `email` → `email_verified`
- `insurance_verified` → `insurance_verified` dimension
- `jobs_completed` → `completed_projects`

Hardwired zeros (Connect source): `id_verified`, `cipc_verified`, `vat_verified`.

## 9. Explicit non-goals

- Trust history/event/evidence tables
- Manual score editing
- Copying Supabase RLS into GHM
- Public HTTP routes unless separately authorized
- Production migration or cutover
