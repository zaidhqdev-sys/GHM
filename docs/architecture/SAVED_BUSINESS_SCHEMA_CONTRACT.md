# GHM Saved Business Schema Contract

**Status:** CONSTRUCTION CONTRACT — SCHEMA DESIGN FROZEN

## 1. Purpose

Define the provider-neutral PostgreSQL schema for the Saved Business account-owned relationship reconciled from the live Zaid Connect source audit.

This contract authorizes construction on the GHM construction branch only. It does not authorize production migration, Supabase changes, product adapters, shadow traffic, credential changes, or cutover.

## 2. Canonical relation

```text
ghm.saved_business
```

Each row records that one authenticated Account has saved one eligible Business for later access.

The relationship is private to the owning Account. It is not a Business membership, Review, Trust score, Enquiry, or Notification capability.

## 3. Canonical columns

| Column | Type | Nullability | Default | Authority |
|---|---|---|---|---|
| `id` | `bigint` identity (`GENERATED BY DEFAULT AS IDENTITY`) | NOT NULL | database | database |
| `account_id` | `bigint` | NOT NULL | none | authenticated Account from `AuthContext.userId` |
| `business_id` | `bigint` | NOT NULL | none | target Business identity |
| `created_at` | `timestamptz` | NOT NULL | `now()` | database |

Exact physical definition:

```text
id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
account_id bigint NOT NULL REFERENCES ghm.account_identity(id) ON DELETE CASCADE
business_id bigint NOT NULL REFERENCES ghm.business(id) ON DELETE CASCADE
created_at timestamptz NOT NULL DEFAULT now()
UNIQUE(account_id, business_id)
```

No Supabase UUID, `auth.uid()`, provider user identifier, provider Business identifier, or RLS-specific column is part of the GHM schema.

## 4. Ownership and identity binding

`account_id` is the canonical owner of the Saved Business relationship.

The authenticated Account must always be taken from `AuthContext.userId`.

A caller-supplied account identifier must not be trusted as authorization proof.

The identity boundary remains:

```text
AuthContext -> authorization boundary -> service -> repository -> authorized transaction
```

No transaction/session variable such as `current_setting('ghm.saved_business_account_id')` is authorized.

## 5. Foreign keys

### Account owner

```text
ghm.saved_business.account_id
  -> ghm.account_identity.id
```

Delete behavior: `ON DELETE CASCADE`.

### Target Business

```text
ghm.saved_business.business_id
  -> ghm.business.id
```

Delete behavior: `ON DELETE CASCADE`.

## 6. Integrity constraints

```text
CONSTRAINT saved_business_account_business_unique
  UNIQUE (account_id, business_id)
```

Concurrent create attempts for the same Account/Business pair must not create duplicate relationships.

## 7. Indexes

Required:

```text
saved_business_account_created_idx
  ON ghm.saved_business (account_id, created_at DESC, id)

saved_business_business_idx
  ON ghm.saved_business (business_id, id)
```

The Account/created-at index supports newest-first owned reads. The Business index supports governed cleanup and dependency inspection.

## 8. Table ownership

```text
OWNER TO ghm_schema_owner
```

Construction and governed cleanup use migrator authority with schema-owner elevation. Runtime operations use `ghm_runtime`.

## 9. Business eligibility for create

Create is allowed only when the target Business currently satisfies:

```text
is_active = true
AND is_verified = true
AND verification_status = 'approved'
```

This predicate is evaluated against the canonical `ghm.business` row. No second eligibility vocabulary is authorized.

A later eligibility change does not, by itself, authorize automatic deletion or expiry in this slice.

## 10. Public Business projection boundary

Saved Business stores only the private relationship columns above.

It must not:

- select `businesses(*)` or equivalent unrestricted Business joins;
- expose private Business workflow fields such as `registration_number`, `directory_review_submitted_at`, `directory_review_last_reason`, or `directory_review_last_event_type`.

Business presentation remains the separately governed public Business projection.

## 11. Runtime privilege boundary

Runtime mutations are function-scoped. Direct table DML beyond SELECT is not granted to `ghm_runtime`.

Required direction:

- `SELECT` on `ghm.saved_business`;
- no table `INSERT`;
- no table `UPDATE`;
- no table `DELETE`;
- `USAGE` on `saved_business_id_seq` (schema default ACL for `ghm` sequences);
- `EXECUTE` on `ghm.create_saved_business(bigint, bigint)`;
- `EXECUTE` on `ghm.delete_saved_business(bigint, bigint)`.

Create and delete functions are `SECURITY DEFINER`, owned by `ghm_schema_owner`, with `search_path = pg_catalog, ghm`.

Direct runtime table INSERT/DELETE remain denied. Mutations are function-scoped so Account ownership and Business eligibility stay inside governed database functions while the application identity boundary remains on `AuthContext`.

## 12. Operation coupling

The schema supports exactly:

```text
saved_business.read
saved_business.create
saved_business.delete
```

There is no toggle operation, no arbitrary UPDATE path, and no anonymous access surface.

## 13. Explicit exclusions

This schema contract does not authorize:

- Trust score calculation;
- folders/tags/collections;
- saved searches or saved enquiries;
- automatic expiry;
- bulk save/unsave;
- anonymous saved state;
- public Saved Business reads;
- notification delivery;
- provider cutover or production migration.
