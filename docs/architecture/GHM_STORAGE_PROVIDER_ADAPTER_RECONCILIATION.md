# GHM Storage Provider Adapter Reconciliation

## Status
**CONSTRUCTION — PROVIDER ADAPTER RECONCILIATION**

The provider-adapter implementation is being reconciled onto the already-qualified PostgreSQL persistence boundary.

The qualified persistence branch remains the source of truth for ghm.storage_object. This slice does not modify the database, grant runtime table privileges, provision a bucket, or enable production credentials.

## Reconciled architecture

1. GHM storage service owns policy and caller/resource authorization.
2. PostgreSQL metadata is owned by the canonical storage persistence functions.
3. The runtime database role reaches storage metadata through those functions rather than direct table DML.
4. The provider adapter owns provider SDK interaction only.
5. Provider keys are generated by the GHM-owned key contract.
6. Provider state is verified before metadata becomes available.
7. Metadata enters deletion_pending before provider deletion and only becomes deleted after provider deletion succeeds.

## Provider implementation gate

The current implementation is S3-compatible and uses the existing AWS SDK dependency. It is intentionally network-free for the focused signing tests.

This slice does not authorize:
- production bucket selection;
- production credentials;
- live uploads;
- live downloads;
- provider reconciliation jobs;
- backup/recovery;
- HTTP exposure.

## Required qualification

Run the focused TypeScript build and storage tests on this exact branch.

A passing result establishes only repository-level provider-adapter construction and compatibility with the qualified persistence boundary. A separate live-provider qualification remains required before production enablement.

## Integrity boundary

Completion checks provider-reported content type and byte size against canonical metadata before the object transitions to available. Provider checksum material may be recorded when available.

## No provider authority

The provider remains an infrastructure capability, not a product authority. Presigned URLs are temporary provider capabilities; authorization decisions remain in GHM.
