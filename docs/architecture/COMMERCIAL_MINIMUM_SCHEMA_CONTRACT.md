# GHM Commercial Capability — Minimum Schema Contract

**Status:** CONSTRUCTION CONTRACT — SCHEMA DESIGN AUTHORIZED
**Date:** 2026-09-15

## 1. Purpose

Define the minimum provider-neutral PostgreSQL schema required for GHM to own the Commercial capability required by the current Zaid Connect and QuoteFlow products.

This contract governs schema construction only. It does not authorize product adapter implementation, provider integration, shadow operation, production data movement, or production cutover.

## 2. Canonical ownership

GHM Commercial is Business-scoped.

Canonical identity remains:

- `ghm.account_identity`
- `ghm.business`
- `ghm.business_membership`

Commercial must not create a second organization/account identity model.

## 3. Schema namespace

All Commercial tables are created under the `ghm` schema.

All GHM-owned relational identifiers use:

`bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`

All timestamps use:

`timestamptz NOT NULL DEFAULT now()`

## 4. Commercial plan

### `ghm.commercial_plan`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `code text NOT NULL UNIQUE`
- `name text NOT NULL`
- `audience text NOT NULL DEFAULT 'business'`
- `lifecycle_status text NOT NULL DEFAULT 'draft'`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- code is lowercase and follows `^[a-z][a-z0-9_]{2,49}$`
- name is 2–100 characters after trimming
- audience is `business`
- lifecycle is `draft | active | retired`

GHM does not create a customer/user plan model in this slice.

## 5. Commercial plan version

### `ghm.commercial_plan_version`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `plan_id bigint NOT NULL REFERENCES ghm.commercial_plan(id) ON DELETE RESTRICT`
- `version integer NOT NULL`
- `trial_days integer NOT NULL DEFAULT 0`
- `founding_limit integer`
- `founding_protection_months integer`
- `effective_from timestamptz NOT NULL`
- `effective_until timestamptz`
- `lifecycle_status text NOT NULL DEFAULT 'draft'`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- version >= 1
- trial_days between 0 and 30
- founding_limit is null or > 0
- founding_protection_months is null or between 1 and 60
- effective_until is null or greater than effective_from
- lifecycle is `draft | active | retired`
- unique `(plan_id, version)`

## 6. Entitlements

### `ghm.commercial_plan_entitlement`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `plan_version_id bigint NOT NULL REFERENCES ghm.commercial_plan_version(id) ON DELETE CASCADE`
- `entitlement_code text NOT NULL`
- `access_level text NOT NULL DEFAULT 'enabled'`
- `metadata jsonb NOT NULL DEFAULT '{}'::jsonb`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- entitlement code matches `^[a-z][a-z0-9.]{2,99}$`
- access level is `enabled`
- metadata is a JSON object
- unique `(plan_version_id, entitlement_code)`

## 7. Regional pricing

### `ghm.commercial_plan_price`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `plan_version_id bigint NOT NULL REFERENCES ghm.commercial_plan_version(id) ON DELETE RESTRICT`
- `country_id bigint REFERENCES ghm.country(id) ON DELETE RESTRICT`
- `currency_id bigint NOT NULL REFERENCES ghm.currency(id) ON DELETE RESTRICT`
- `price_kind text NOT NULL`
- `amount_minor_units bigint NOT NULL`
- `billing_interval text NOT NULL DEFAULT 'month'`
- `effective_from timestamptz NOT NULL`
- `effective_until timestamptz`
- `lifecycle_status text NOT NULL DEFAULT 'draft'`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- price kind is `founding | standard`
- amount is >= 0
- billing interval is `month`
- effective_until is null or greater than effective_from
- lifecycle is `draft | active | retired`

Country is optional because pricing must not require a duplicated regional-configuration system.

## 8. Commercial trial

### `ghm.commercial_trial`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `business_id bigint NOT NULL REFERENCES ghm.business(id) ON DELETE RESTRICT`
- `plan_version_id bigint NOT NULL REFERENCES ghm.commercial_plan_version(id) ON DELETE RESTRICT`
- `activated_by bigint NOT NULL REFERENCES ghm.account_identity(id) ON DELETE RESTRICT`
- `activated_at timestamptz NOT NULL DEFAULT now()`
- `expires_at timestamptz NOT NULL`
- `lifecycle_status text NOT NULL DEFAULT 'active'`
- `ended_at timestamptz`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- expires_at > activated_at
- lifecycle is `active | expired | converted | cancelled`
- active => ended_at IS NULL
- non-active => ended_at IS NOT NULL
- unique business_id

This preserves Connect's one-trial-per-Business invariant.

## 9. Commercial subscription

### `ghm.commercial_subscription`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `business_id bigint NOT NULL REFERENCES ghm.business(id) ON DELETE RESTRICT`
- `plan_version_id bigint NOT NULL REFERENCES ghm.commercial_plan_version(id) ON DELETE RESTRICT`
- `price_id bigint REFERENCES ghm.commercial_plan_price(id) ON DELETE RESTRICT`
- `trial_id bigint UNIQUE REFERENCES ghm.commercial_trial(id) ON DELETE RESTRICT`
- `lifecycle_status text NOT NULL`
- `current_period_start timestamptz`
- `current_period_end timestamptz`
- `cancel_at_period_end boolean NOT NULL DEFAULT false`
- `cancelled_at timestamptz`
- `founding_sequence integer`
- `founding_protected_until timestamptz`
- `provider_reference text`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Lifecycle states:

- `trialing`
- `active`
- `past_due`
- `grace_period`
- `cancel_at_period_end`
- `cancelled`
- `expired`
- `suspended`

Constraints:

- period end is null OR both period values exist and end > start
- founding sequence is null OR > 0
- `cancel_at_period_end` is consistent with the cancellation lifecycle state
- provider reference is opaque provider metadata only
- Free subscriptions have `price_id IS NULL`.
- Paid subscriptions have `price_id IS NOT NULL`.

The schema must not encode Paystack or PayFast-specific columns.

## 10. Payment attempt

### `ghm.commercial_payment_attempt`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `business_id bigint NOT NULL REFERENCES ghm.business(id) ON DELETE RESTRICT`
- `subscription_id bigint REFERENCES ghm.commercial_subscription(id) ON DELETE RESTRICT`
- `price_id bigint NOT NULL REFERENCES ghm.commercial_plan_price(id) ON DELETE RESTRICT`
- `initiated_by bigint NOT NULL REFERENCES ghm.account_identity(id) ON DELETE RESTRICT`
- `attempt_status text NOT NULL DEFAULT 'pending_checkout'`
- `amount_minor_units bigint NOT NULL`
- `currency_id bigint NOT NULL REFERENCES ghm.currency(id) ON DELETE RESTRICT`
- `billing_interval text NOT NULL DEFAULT 'month'`
- `checkout_reference text`
- `idempotency_key text NOT NULL UNIQUE`
- `expires_at timestamptz`
- `failure_code text`
- `failure_message text`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Attempt states:

- `pending_checkout`
- `pending_payment`
- `succeeded`
- `failed`
- `expired`
- `cancelled`

Constraints:

- amount > 0
- billing interval is `month`
- idempotency key length 8–200
- checkout reference length <= 200 when present
- failed attempts require failure_code
- failure message is bounded

## 11. Payment transaction

### `ghm.commercial_payment_transaction`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `business_id bigint NOT NULL REFERENCES ghm.business(id) ON DELETE RESTRICT`
- `subscription_id bigint NOT NULL REFERENCES ghm.commercial_subscription(id) ON DELETE RESTRICT`
- `payment_attempt_id bigint REFERENCES ghm.commercial_payment_attempt(id) ON DELETE RESTRICT`
- `provider_event_id bigint REFERENCES ghm.commercial_provider_event(id) ON DELETE RESTRICT`
- `transaction_kind text NOT NULL DEFAULT 'payment'`
- `transaction_status text NOT NULL`
- `amount_minor_units bigint NOT NULL`
- `currency_id bigint NOT NULL REFERENCES ghm.currency(id) ON DELETE RESTRICT`
- `provider_transaction_reference text`
- `occurred_at timestamptz NOT NULL`
- `recorded_at timestamptz NOT NULL DEFAULT now()`
- `metadata jsonb NOT NULL DEFAULT '{}'::jsonb`

Transaction kinds:

- `payment`
- `refund`
- `reversal`
- `chargeback`

Transaction states:

- `pending`
- `succeeded`
- `failed`

Constraints:

- amount > 0
- metadata must be a JSON object
- provider transaction reference is opaque
- when provider_event_id is present, a provider event may produce at most one payment transaction

## 12. Provider events

### `ghm.commercial_provider_event`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `provider_code text NOT NULL`
- `provider_event_id text NOT NULL`
- `event_type text NOT NULL`
- `payload_hash text NOT NULL`
- `received_at timestamptz NOT NULL DEFAULT now()`
- `occurred_at timestamptz`
- `processing_status text NOT NULL DEFAULT 'received'`
- `processed_at timestamptz`
- `failure_reason text`
- `metadata jsonb NOT NULL DEFAULT '{}'::jsonb`

Constraints:

- provider code matches `^[a-z][a-z0-9_]{1,49}$`
- provider event ID length 1–200
- event type length 1–100
- payload hash is 64 lowercase hexadecimal characters
- processing status is `received | processed | ignored | failed`
- received => processed_at IS NULL
- non-received => processed_at IS NOT NULL
- unique `(provider_code, provider_event_id)`
- `occurred_at` is nullable because a provider event may not supply a trustworthy occurrence timestamp.
- When `occurred_at` is absent, `received_at` is the authoritative GHM ingestion timestamp.
- GHM must not silently copy `received_at` into `occurred_at`; the two timestamps preserve distinct meanings.
- metadata is a JSON object

This table is the provider-neutral idempotency/audit boundary.

## 13. Commercial events

### `ghm.commercial_event`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `business_id bigint REFERENCES ghm.business(id) ON DELETE RESTRICT`
- `subscription_id bigint REFERENCES ghm.commercial_subscription(id) ON DELETE RESTRICT`
- `event_type text NOT NULL`
- `actor_account_id bigint REFERENCES ghm.account_identity(id) ON DELETE SET NULL`
- `source text NOT NULL`
- `idempotency_key text`
- `payload jsonb NOT NULL DEFAULT '{}'::jsonb`
- `occurred_at timestamptz NOT NULL DEFAULT now()`
- `created_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- event type and source are nonblank
- payload is a JSON object
- idempotency is unique when supplied

Commercial events are append-only audit facts.

## 14. Founding allocation

### `ghm.commercial_founding_allocation`

Columns:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `business_id bigint NOT NULL UNIQUE REFERENCES ghm.business(id) ON DELETE RESTRICT`
- `subscription_id bigint NOT NULL UNIQUE REFERENCES ghm.commercial_subscription(id) ON DELETE RESTRICT`
- `payment_transaction_id bigint NOT NULL UNIQUE REFERENCES ghm.commercial_payment_transaction(id) ON DELETE RESTRICT`
- `plan_version_id bigint NOT NULL REFERENCES ghm.commercial_plan_version(id) ON DELETE RESTRICT`
- `founding_sequence integer NOT NULL UNIQUE`
- `protected_until timestamptz NOT NULL`
- `allocated_at timestamptz NOT NULL DEFAULT now()`
- `created_at timestamptz NOT NULL DEFAULT now()`

Constraints:

- founding sequence > 0
- protected_until > allocated_at
- one founding allocation per Business
- one founding allocation per subscription
- one founding allocation per qualifying payment transaction

## 15. Subscription uniqueness

GHM must prevent multiple simultaneously active commercial subscriptions for the same Business.

The implementation must use a database-enforced uniqueness boundary appropriate to the lifecycle states.

The exact partial unique index belongs in the migration and must cover all states that represent an active/current subscription.

## 16. Index requirements

At minimum:

- subscription by business and lifecycle
- trial by business
- payment attempts by business and created_at
- payment transactions by business and occurred_at
- provider events by provider/event identity
- payment transactions by provider event identity when a provider event is present
- commercial events by business and occurred_at
- commercial events by subscription and occurred_at
- plan versions by plan/version
- active/effective pricing lookup
- entitlements by plan version
- founding allocation by sequence

Indexes must support the governed access paths; no generic query indexes are required.

## 17. Timestamp maintenance

Tables containing `updated_at` must receive the established GHM `updated_at` maintenance convention.

Commercial event records are append-only and do not receive update semantics.

## 18. Runtime privilege boundary

Runtime receives only the minimum privileges required by the eventual Commercial repositories.

Default position:

- SELECT where read operations require it
- INSERT only on records the application is permitted to create
- UPDATE only where the resource contract requires it
- DELETE is not granted to Commercial runtime tables unless a later contract explicitly proves replacement/deletion semantics

No blanket `ALL` privilege.

No runtime ownership of Commercial tables.

Normal runtime application access is limited to the governed Commercial resource/service operations.

Provider callback processing is a separate internal boundary. Provider callbacks may record provider-event and payment-result state only through governed Commercial service logic; they do not receive public resource CRUD access or unrestricted table privileges.

Sequences receive only the required runtime usage/select privileges.

### Commercial Resource/API boundary

The Commercial capability is exposed through governed resource/service operations only.

The initial resource boundary is limited to these semantic operations:

- read commercial access for an authorized Business
- activate a Business commercial trial
- prepare a paid subscription payment attempt
- read the Business subscription state
- schedule cancellation at period end
- apply a governed provider payment result through the internal provider boundary
- expire eligible commercial access through a governed lifecycle operation

The API must not expose generic table CRUD, arbitrary field updates, direct provider-event mutation, direct payment-transaction mutation, or direct founding-allocation mutation.

Each operation must resolve authorization through the existing GHM `AuthContext` and Business membership model before mutating Commercial state.

Provider callback handling is not a public Commercial resource operation. It is an internal boundary that enters governed Commercial service logic.


## 19. Authorization boundary

Business-scoped Commercial operations require:

- authenticated `AuthContext`
- valid Business context
- active Business membership where appropriate
- `owner` or `administrator` for Business management mutations

Ordinary active `member` access does not imply commercial management authority.

Admin handling remains governed by existing GHM authorization semantics.

Provider callback handling is a separate internal/provider boundary and must not bypass auditability.

## 20. Transaction boundary

Commercial state transitions involving multiple records must execute through the established GHM authorized transaction mechanism.

Examples:

- trial activation
- subscription creation/update
- payment attempt preparation
- payment result application
- founding allocation
- cancellation scheduling

Partial Commercial state must never become visible because one step succeeded while another failed.

## 21. Concurrency and idempotency

The database and repository layer must jointly guarantee:

- one trial per Business
- one current subscription per Business
- unique payment attempt idempotency key
- unique provider event identity
- no duplicate payment transaction for an already-processed provider event
- no duplicate founding allocation
- founding sequence allocation is concurrency-safe
- subscription transitions cannot overwrite a newer lifecycle state accidentally

Founding sequence allocation must be serialized at the Business/plan-version allocation boundary so concurrent successful payments cannot receive the same sequence.

The implementation must use a database-enforced serialization mechanism within the governing transaction. The exact mechanism is to be selected and evidenced during migration and repository qualification; this contract does not assume an existing GHM locking primitive.

## 22. Provider neutrality

GHM must not contain:

- Paystack-specific tables
- PayFast-specific tables
- provider-specific API payload columns
- Supabase RPC names
- Supabase auth functions
- Supabase service-role concepts
- regional configuration tables copied from Connect

Provider identity is represented only through opaque provider codes/references and governed provider events.

## 23. Product mapping boundary

Connect concepts map into GHM Commercial semantics through an adapter.

QuoteFlow's `organization` maps to `ghm.business`.

No `organization` table is introduced for QuoteFlow.

Connect's UUID provider identifiers are not copied into GHM primary keys.

Adapters own identifier translation.

## 24. Launch authorization

Connect's `commercial_launch_authorized` remains a Connect/product deployment gate.

It is not a GHM subscription state.

GHM Commercial determines commercial state and entitlement.

The product adapter determines whether a particular product release is commercially enabled.

### Reference-data authority

Commercial foreign keys to `ghm.country` and `ghm.currency` reference existing canonical GHM rows.

Commercial schema construction must not assume fixed IDs and must not silently create or seed country/currency records.

Any required canonical country/currency rows must be established through a separately governed reference-data migration or existing canonical seed authority before Commercial qualification.


## 25. Seed data

Schema construction must not silently seed production commercial plans, prices, entitlements, or founding allocations.

Any canonical seed data requires an explicit, separately governed migration decision.

## 26. Non-goals

This schema does not construct:

- Paystack integration
- PayFast integration
- checkout UI
- webhook HTTP endpoints
- provider signature verification
- product adapters
- QuoteFlow migration
- Connect migration
- shadow traffic
- production data movement
- production cutover

## 27. Acceptance criteria

Schema construction is accepted only when:

1. all tables exist in `ghm`
2. all columns and constraints match this contract
3. all FKs target canonical GHM resources
4. lifecycle constraints reject invalid states
5. uniqueness/idempotency boundaries are database-enforced
6. timestamp maintenance is evidenced
7. runtime ACL is explicitly qualified
8. runtime cannot mutate provider/audit records outside the governed contract
9. founding allocation is concurrency-safe and its database serialization boundary is evidenced
10. migration is reversible only where safely possible and otherwise documented as forward-only
11. build/tests remain passing
12. dedicated qualification evidence exists
13. no Supabase/provider implementation leaks into GHM

## 28. Production boundary

This contract authorizes schema construction and qualification only.

It does not authorize:

- production cutover
- production data migration
- Supabase shutdown
- DNS/routing changes
- provider credential migration
- live payment processing through GHM
- shadow production operation

Those require separate product-adapter, shadow-qualification, and controlled-cutover gates.
