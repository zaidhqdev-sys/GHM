# Project Quote Schema Contract

**Status:** QUALIFIED / CLOSED / PASS — schema constructed, migrated, and runtime-qualified 2026-09-14

## 1. Purpose

Define the canonical GHM PostgreSQL schema for Project Quotes.

This schema is provider-neutral and preserves the verified Zaid Connect Project Quote capability while using the established GHM identity model.

The canonical relation is:

`ghm.project_quote`

No Supabase UUID, `auth.uid()`, RLS policy, RPC, or provider-specific identifier is part of this schema contract.

## 2. Canonical Relation

`ghm.project_quote`

Each row represents one Business quote submitted against one customer-owned Project.

## 3. Identity and Ownership

### Project

`project_id` references:

`ghm.project.id`

Project ownership remains governed by:

`ghm.project.account_id -> ghm.account_identity.id`

### Business

`business_id` references:

`ghm.business.id`

The Business is the submitting organization.

Quote authority is established by the application authorization boundary and authenticated account context, not by a caller-supplied owner identifier.

The schema must not introduce a second ownership model.

## 4. Columns

The canonical columns are:

- `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `project_id bigint NOT NULL`
- `business_id bigint NOT NULL`
- `amount numeric(12,2) NOT NULL`
- `labour_min numeric(12,2)`
- `labour_max numeric(12,2)`
- `materials_min numeric(12,2)`
- `materials_max numeric(12,2)`
- `total_min numeric(12,2)`
- `total_max numeric(12,2)`
- `duration_days integer`
- `description text`
- `status text NOT NULL DEFAULT 'submitted'`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

No additional provider-derived identity columns are authorized.

## 5. Foreign Keys

`project_id` references:

`ghm.project(id)`

`business_id` references:

`ghm.business(id)`

Both relationships must prevent orphaned Project Quote records.

The initial construction contract uses:

- `ON DELETE RESTRICT` for Project ? Project Quote;
- `ON DELETE RESTRICT` for Business ? Project Quote.

Project deletion is separately governed by the Project resource contract and is not enabled merely because the foreign key cascades.

Project or Business deletion must not silently erase quote history.

## 6. Quote Uniqueness

Only one quote may exist for a given Business on a given Project.

Canonical constraint:

`UNIQUE (project_id, business_id)`

This preserves the verified Connect rule that a Business cannot submit duplicate quotes against the same Project.

## 7. Financial Validation

`amount` must satisfy:

`amount >= 0`

If `labour_min` is present:

`labour_min >= 0`

If `labour_max` is present:

`labour_max >= 0`

If both labour bounds are present:

`labour_max >= labour_min`

If `materials_min` is present:

`materials_min >= 0`

If `materials_max` is present:

`materials_max >= 0`

If both materials bounds are present:

`materials_max >= materials_min`

If `total_min` is present:

`total_min >= 0`

If `total_max` is present:

`total_max >= 0`

If both total bounds are present:

`total_max >= total_min`

The database must enforce these invariants.

## 8. Duration Validation

`duration_days` is optional.

When present it must be an integer between:

`1` and `3650`

The database must reject values outside this range.

## 9. Description Validation

`description` is optional.

When present:

- trimmed length must be at least 10 characters;
- trimmed length must be at most 5000 characters.

The database must enforce the same boundary as the provider-neutral operation contract.

## 10. Status Vocabulary

The canonical status vocabulary is:

- `submitted`
- `accepted`
- `rejected`
- `withdrawn`

The initial status is:

`submitted`

The database must reject arbitrary status values.

Only the following states are exercised by the current GHM Project Quote operation contract:

- `submitted`
- `accepted`
- `rejected`

`withdrawn` is retained as canonical vocabulary for provider capability compatibility but has no current GHM operation.

No arbitrary lifecycle mutation is authorized.

## 11. Accepted-Quote Invariant

A Project may have at most one accepted quote.

Canonical database invariant:

a partial unique index on `project_id` for rows where:

`status = 'accepted'`

This is a defense-in-depth invariant.

Application authorization and transaction locking remain responsible for the complete acceptance decision.

## 12. Indexes

Required indexes:

### Project history

`(project_id, created_at DESC)`

Supports customer reads of received quotes and project quote history.

### Business history

`(business_id, created_at DESC)`

Supports Business reads of its own submitted quotes.

### Project status filtering

`(project_id, status)`

Supports decision and lifecycle checks.

### Accepted uniqueness

Unique partial index:

`(project_id) WHERE status = 'accepted'`

No speculative indexes are authorized at this stage.

## 13. Project Lifecycle Relationship

Project Quote creation and update are permitted only while the referenced Project is:

`open`

Accepting a submitted quote performs the compound Project Quote decision:

1. authorize the authenticated Project owner;
2. lock the selected quote;
3. verify the selected quote is `submitted`;
4. lock the Project;
5. verify the Project is `open`;
6. reject all other submitted quotes for that Project;
7. accept the selected quote;
8. transition the Project to `in_progress`;
9. commit atomically.

The schema must support this operation but must not independently implement arbitrary Project lifecycle transitions.

## 14. Runtime Privilege Direction

The runtime role is not a schema owner.

The intended minimum direction is:

### Schema

`USAGE` on schema `ghm`.

### Project Quote SELECT

`SELECT` on `ghm.project_quote`.

### Project Quote INSERT

`INSERT` only on:

- `project_id`
- `business_id`
- `amount`
- `labour_min`
- `labour_max`
- `materials_min`
- `materials_max`
- `total_min`
- `total_max`
- `duration_days`
- `description`

The runtime role must not control:

- `id`
- `status`
- `created_at`
- `updated_at`

### Project Quote UPDATE

`UPDATE` only on mutable quote detail fields:

- `amount`
- `labour_min`
- `labour_max`
- `materials_min`
- `materials_max`
- `total_min`
- `total_max`
- `duration_days`
- `description`
- `updated_at`

The runtime role must not receive a generic lifecycle/status API authority. Column-level UPDATE(status) is required only so the repository can execute the explicitly authorized accept/reject decision operations within the established transaction boundary; application authorization remains mandatory.

Acceptance and rejection are compound authorized operations and must be implemented through repository transactions using the established authorization boundary.

### DELETE

No runtime `DELETE` privilege.

## 15. Acceptance/Rejection Privilege Dependency

Atomic acceptance requires access to the existing Project relation.

The final runtime grant must be measured against the existing qualified Project privileges rather than granting broad access. Acceptance requires the narrowly measured ability to set the Project status from open to in_progress; this is a Project Quote decision dependency, not a new generic Project lifecycle operation.

The acceptance transaction may require:

- reading the selected Project;
- locking the selected Project;
- reading competing Project Quotes;
- updating quote statuses;
- updating the Project lifecycle status.

Any additional Project privilege must be explicitly documented and qualified.

No blanket:

`GRANT ALL`

is authorized.

## 16. Sequence Privilege

Because `id` is identity-backed, runtime creation requires appropriate sequence usage.

The final migration must grant only the required sequence privilege for:

`ghm.project_quote_id_seq`

Default sequence privileges must also remain consistent with the established GHM runtime model.

## 17. Business Eligibility

The schema does not encode Business verification as ownership authority.

Quote creation/update eligibility is application-governed and requires:

- authenticated account;
- the exact Business authority defined by the Project Quote operation contract;
- `ghm.business.is_active = true`;
- `ghm.business.is_verified = true`;
- `ghm.business.verification_status = 'approved'`;
- Project is open;
- Business is not the Project customer.

The existing Business verification invariant remains authoritative.

## 18. Customer Ownership

Customer quote reads and quote decisions are governed through:

`ghm.project.account_id = AuthContext.userId`

The quote table must not duplicate Project ownership.

The customer account must not be stored as a second authority field on the quote.

## 19. Business Ownership

Business quote reads and quote mutations are governed through the established Business Identity membership/ownership boundary.

The quote table must not duplicate Business owner account identity.

Business administrator authority is not expanded by this schema contract.

## 20. Delete Semantics

No Project Quote delete operation is authorized.

Quote history is durable.

Project deletion policy remains governed by the Project resource contract and must not be inferred from quote foreign-key behavior alone.

## 21. Provider-Neutral Boundary

The schema must not contain:

- Supabase UUIDs;
- `auth.uid()`;
- RLS policies;
- security-definer functions;
- provider-specific RPC identifiers;
- provider-specific user identifiers;
- provider-specific business identifiers.

GHM IDs are canonical.
