## 1. Repository conventions adopted

| Convention | Evidence / rule |
|---|---|
| Schema | `ghm` |
| Table names | `snake_case` resource nouns (`ghm.campaign`, `ghm.saved_business`) |
| PK | `bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| Timestamps | `timestamptz NOT NULL DEFAULT now()`; `updated_at` where mutable |
| Account FK column | `account_id` → `ghm.account_identity(id)` |
| Business FK | `business_id` → `ghm.business(id)` |
| CHECK names | `<table>_<field>_check` or `<table>_<field>_valid` |
| Indexes | `<table>_<purpose>_idx` |
| Ownership | `ALTER TABLE … OWNER TO ghm_schema_owner` |
| Mutations | Prefer `SECURITY DEFINER` + `SET search_path = pg_catalog, ghm` |
| Runtime | `REVOKE INSERT, UPDATE, DELETE` on sensitive tables; `GRANT EXECUTE` on approved functions |
| Roles | `ghm_schema_owner` / `ghm_migrator` / `ghm_runtime` |

**ON DELETE defaults for this contract:**

| Relationship | Proposed | Rationale |
|---|---|---|
| Auth rows → `account_identity` | `ON DELETE CASCADE` | Credential/session/recovery/mapping owned by identity; identity is not casually deleted |
| Business mapping → `business` | `ON DELETE RESTRICT` | Preserve mapping integrity; do not silently drop product linkages |
| Refresh → session | `ON DELETE CASCADE` | Lineage dies with session |
| Self-FK refresh predecessor | `ON DELETE SET NULL` | History optional if predecessor purged |

Canonical identity must not be casually deletable in product flows; hard delete remains a separate governed operation.

## 6. Email / login identity + password credential

### Ownership decision (proposed)

**Email lives on the password credential relation**, not on `account_identity` profile.

**Reasoning (first gate):**

- Founder: email is **login identifier**; password is first credential.
- `account_identity` today has no email; profile fields are person metadata.
- One canonical login email per account for first implementation.
- Avoids a third table when only password login exists.
- Future alternate login factors can add relations later without forcing email onto the person row now.

### Proposed table: `ghm.account_password_credential`

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `account_id` | `bigint` | NOT NULL | — | **PK** and FK → `account_identity(id)` ON DELETE CASCADE |
| `login_email` | `text` | NOT NULL | — | Original accepted form (trimmed); not used as unique key alone |
| `login_email_normalized` | `text` | NOT NULL | — | Canonical lookup key |
| `password_hash` | `text` | NOT NULL | — | Argon2id encoded hash (library format may embed params) |
| `argon2_memory_kib` | `integer` | NULL | — | Optional explicit params if not fully embedded in hash string |
| `argon2_time_cost` | `integer` | NULL | — | Optional |
| `argon2_parallelism` | `integer` | NULL | — | Optional |
| `credential_status` | `text` | NOT NULL | `'active'` | CHECK `active`/`disabled` |
| `password_changed_at` | `timestamptz` | NOT NULL | `now()` | |
| `created_at` | `timestamptz` | NOT NULL | `now()` | |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | |

**Cardinality:** exactly **one** password credential row per account in the first implementation (`account_id` PK).

**Uniqueness:** `UNIQUE (login_email_normalized)`

**Normalization (approved first-gate login key — not full internationalized email / IDNA):**

```text
trim → deterministic NFKC → case normalization → login_email_normalized
```

- `login_email` stores the trimmed accepted form (display / outbound).
- `login_email_normalized` stores the runtime-produced canonical login key.
- Uniqueness is enforced on `login_email_normalized` only.
- The database does **not** perform NFKC/casefold; the Auth runtime writes the already-normalized key.
- This does **not** claim full IDNA, SMTPUTF8, or provider-specific mailbox semantics.

**Indexes:** unique constraint on `login_email_normalized` is sufficient for login/recovery lookup.

**Must not:** store plaintext passwords; store password history in first gate.

## 7. Authentication session

### Proposed table: `ghm.authentication_session`

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint` identity | NOT NULL | generated | PK |
| `account_id` | `bigint` | NOT NULL | — | FK → `account_identity` ON DELETE CASCADE |
| `session_status` | `text` | NOT NULL | `'active'` | CHECK `active`/`revoked` |
| `created_at` | `timestamptz` | NOT NULL | `now()` | Session start (absolute clock) |
| `last_seen_at` | `timestamptz` | NOT NULL | `now()` | Updated on successful refresh |
| `absolute_expires_at` | `timestamptz` | NOT NULL | — | Set at create: `created_at + 90 days` |
| `revoked_at` | `timestamptz` | NULL | — | Set on revoke |
| `revoke_reason` | `text` | NULL | — | e.g. `logout`, `replay`, `password_change`, `password_recovery`, `account_disabled` (vocabulary implementation-owned) |

**Expiry representation:** **stored timestamps** (simplest reliable):

- Absolute: `absolute_expires_at`
- Inactivity: enforce `now() < last_seen_at + 30 days` at refresh (no separate column required)

**Session family:** the session `id` **is** the family id. All `refresh_credential` rows for that session share the family. Revoking the session revokes the family.

**Indexes (proposed):**

| Index | Definition | Why |
|---|---|---|
| `authentication_session_account_status_idx` | `(account_id, session_status, id)` | List/revoke all sessions for account |
| `authentication_session_active_abs_idx` | partial `(absolute_expires_at)` WHERE `session_status = 'active'` | Optional cleanup — **defer** unless ops need it |

## 8. Refresh credential / lineage

### Proposed table: `ghm.refresh_credential`

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint` identity | NOT NULL | generated | PK |
| `session_id` | `bigint` | NOT NULL | — | FK → `authentication_session` ON DELETE CASCADE |
| `token_hash` | `bytea` or `text` | NOT NULL | — | Hash/reference of opaque secret; **UNIQUE** |
| `issued_at` | `timestamptz` | NOT NULL | `now()` | |
| `used_at` | `timestamptz` | NULL | — | Set when rotated successfully |
| `revoked_at` | `timestamptz` | NULL | — | Family/account revoke |
| `predecessor_id` | `bigint` | NULL | — | FK → `refresh_credential(id)` ON DELETE SET NULL |

**Live tip:** the unique row for a session with `used_at IS NULL AND revoked_at IS NULL` (at most one — enforced by transaction discipline; optional unique partial index):

```text
UNIQUE INDEX refresh_credential_session_live_uidx
  ON ghm.refresh_credential (session_id)
  WHERE used_at IS NULL AND revoked_at IS NULL
```

**Proposed:** include this partial unique index — prevents two live tips per session.

**Opaque secret (approved storage):** 32-byte CSPRNG token; wire = URL-safe base64 (no padding).

**Protected DB representation (approved):**

```text
token_hash = HMAC-SHA256(GHM_AUTH_TOKEN_PEPPER, purpose || raw_token_bytes) AS bytea
```

- Pepper is a **runtime secret** (`GHM_AUTH_TOKEN_PEPPER`); never stored in the database or migrations.
- Optional purpose domain separation: `refresh:` / `recovery:` prefixes in the HMAC message.
- Raw refresh/recovery tokens are **never** persisted.

### Successful refresh (atomic)

```text
BEGIN
  SELECT session … FOR UPDATE
  validate session active + inactivity + absolute
  UPDATE refresh_credential
     SET used_at = now()
   WHERE id = :id
     AND used_at IS NULL
     AND revoked_at IS NULL
  -- if 0 rows: treat as reuse/invalid → replay path
  INSERT successor refresh_credential (session_id, token_hash, predecessor_id)
  UPDATE session SET last_seen_at = now()
  -- issue access JWT in app layer
COMMIT
```

### Replay

```text
presented hash matches row with used_at IS NOT NULL
        OR revoked_at IS NOT NULL
        ↓
revoke session (session_status=revoked, revoked_at=now(), reason=replay)
        ↓
revoke all refresh rows for session (revoked_at=now())
        ↓
fail 401 REFRESH_CREDENTIAL_REUSED / SESSION_REVOKED
```

### Concurrency

Two concurrent refreshes of the same live credential: exactly one `UPDATE … used_at IS NULL` wins; the other gets 0 rows → must not mint a second successor. Partial unique live index + row lock on session provide safety.

## 9. Recovery credential

### Proposed table: `ghm.password_recovery_credential`

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint` identity | NOT NULL | generated | PK |
| `account_id` | `bigint` | NOT NULL | — | FK → `account_identity` ON DELETE CASCADE |
| `token_hash` | `bytea` or `text` | NOT NULL | — | UNIQUE |
| `created_at` | `timestamptz` | NOT NULL | `now()` | |
| `expires_at` | `timestamptz` | NOT NULL | — | created + TTL (TTL UNSELECTED) |
| `used_at` | `timestamptz` | NULL | — | |
| `revoked_at` | `timestamptz` | NULL | — | |

**Indexes:** `UNIQUE (token_hash)`; `(account_id, created_at DESC)` for optional cleanup.

**Redemption atomicity:** `UPDATE … SET used_at = now() WHERE id = :id AND used_at IS NULL AND revoked_at IS NULL AND expires_at > now()` — 0 rows ⇒ invalid/expired/reused.

On success: replace password hash; revoke **all** sessions for `account_id`; do not mint session.

**Email provider:** UNSELECTED.

## 10. External person identity mapping

### Proposed table: `ghm.account_external_identity`

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint` identity | NOT NULL | generated | PK |
| `provider` | `text` | NOT NULL | — | **SELECTED:** for Supabase Auth subjects use `provider = 'supabase'`. Other future IdPs may use additional provider strings; vocabulary for non-Supabase IdPs remains open. |
| `subject` | `text` | NOT NULL | — | External subject string (Supabase Auth user UUID as text) |
| `account_id` | `bigint` | NOT NULL | — | FK → `account_identity` ON DELETE CASCADE |
| `created_at` | `timestamptz` | NOT NULL | `now()` | |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | |

**Constraints:** `UNIQUE (provider, subject)`
**Index:** `(account_id, provider)` for “list external ids for account”

**Invariants:**

```text
(provider, subject) → at most one account_id
one account_id → many (provider, subject) allowed
```

**Provider vocabulary (SELECTED):**

```text
provider = "supabase"
subject  = Supabase Auth user UUID as text
```

Do **not** use product-scoped provider strings (`supabase-quoteflow`, `supabase-zaid-connect`). Subjects from multiple products/projects may share provider `supabase`; that does **not** imply they are the same person. Cross-product linkage to one GHM account requires **explicit governed link** of multiple subjects to the same `account_id`.

**Email is not the external mapping key.** Email may appear in operator conflict reports only; it must never silently authorize a link.

Supabase Auth UUID subjects migrate as `(provider, subject)` text; they never become JWT `sub`.

**Operations:**

| Op | Function | Behavior |
|---|---|---|
| Bootstrap | `ghm.auth_bootstrap_external_identity` | Missing mapping → create **minimum** `account_identity` + mapping |
| Link | `ghm.auth_link_external_identity` | Missing mapping → attach to **existing** `account_id` only; never create account |
| Lookup | `ghm.auth_lookup_external_identity` | Read mapping |

Link outcomes: `created` \| `already_linked` \| `conflict` \| `account_not_found`. Linking a **disabled** account is permitted; `account_status` is **not** changed (mapping ≠ activation).

Lifecycle/revocation column: **not required** for first gate (delete row = unlink). Soft-disable can be added later if evidence requires.

## 14. Concurrency & transactions

| Operation | Strategy |
|---|---|
| Refresh | Session `FOR UPDATE`; conditional `UPDATE used_at`; partial unique live tip; loser ⇒ fail / replay handling |
| Recovery redeem | Conditional `UPDATE used_at` with expiry predicate |
| Bootstrap | `INSERT` mapping with `UNIQUE (provider, subject)`; on conflict resolve existing `account_id`; never create second identity for same pair |
| Email uniqueness | UNIQUE `login_email_normalized`; conflict ⇒ controlled error (anti-enumeration on public APIs) |
| Account disable | Transaction: set `account_status=disabled`; revoke all sessions + refresh rows for account — so a concurrent refresh cannot leave a new live session |

## 15. SECURITY DEFINER / GRANT model (R6)

### Runtime principle

```text
ghm_runtime
  ↓
EXECUTE only on approved mutation functions
  ↓
SECURITY DEFINER (OWNER ghm_schema_owner)
  ↓
SET search_path = pg_catalog, ghm
```

### Tables (proposed grants after creation)

| Privilege | `ghm_runtime` |
|---|---|
| `SELECT` | Only if Auth API/verify path needs direct reads **or** hide behind functions — prefer minimal SELECT on non-secret columns; **no SELECT of password_hash/token_hash from runtime app role if avoidable** |
| `INSERT`/`UPDATE`/`DELETE` | **REVOKED** on all auth secret/session tables |

### Proposed controlled functions (names illustrative — freeze at implementation)

| Function (proposed) | Purpose |
|---|---|
| `ghm.auth_bootstrap_external_identity` | Mapping + min identity create |
| `ghm.auth_link_external_identity` | Link existing account to `(provider, subject)` without minting identity |
| `ghm.auth_lookup_external_identity` | Read mapping by `(provider, subject)` |
| `ghm.auth_set_password` / `auth_change_password` | Password hash write |
| `ghm.auth_create_session_with_refresh` | Login session + first refresh |
| `ghm.auth_rotate_refresh` | Atomic refresh rotation |
| `ghm.auth_revoke_session` | Logout / single family |
| `ghm.auth_revoke_all_sessions_for_account` | Recovery / disable / admin |
| `ghm.auth_issue_recovery` | Create recovery hash row |
| `ghm.auth_redeem_recovery` | Redeem + password replace + revoke all sessions |
| `ghm.auth_disable_account` | Status + revoke all sessions |
| `ghm.auth_set_system_admin` | Governed admin flag change |
| `ghm.auth_link_business_external_mapping` | LINK-ONLY: attach `(provider, external_business_id)` to existing `business.id` (canonical; replaces proposed `auth_upsert_business_external_mapping`) |

**SELECT-heavy verify path** (load account by id / email): may use narrow `SECURITY DEFINER` readers or tightly column-limited SELECT grants — choose at implementation; **must not** expose hashes to logs or product responses.

Do not make every read a DEFINER function without need.

## 16. Proposed migration order

Safest dependency-aware sequence (filenames/timestamps assigned at implementation):

```text
1. ALTER ghm.account_identity
     ADD account_status, is_system_admin
     (+ backfill active / admin→is_system_admin)
2. CREATE ghm.account_password_credential
3. CREATE ghm.account_external_identity
4. CREATE ghm.business_external_mapping
5. CREATE ghm.authentication_session
6. CREATE ghm.refresh_credential
     (+ partial unique live tip index)
7. CREATE ghm.password_recovery_credential
8. CREATE controlled SECURITY DEFINER functions (auth_*)
9. REVOKE broad DML; GRANT EXECUTE to ghm_runtime
10. Application Auth API / verifier cutover (separate implementation gate)
```

**Rationale:** identity columns first; credentials/mappings next; sessions before refresh (FK); recovery independent after account; functions/grants last so objects exist.

`role` column **not** dropped in this sequence.
