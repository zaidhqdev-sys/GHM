# GHM Campaign Schema Contract

**Status:** CONSTRUCTION CONTRACT — SCHEMA DESIGN FROZEN
**Resource:** `campaign`
**Purpose:** KBM AI Marketing backend root container
**Depends on:** [CAMPAIGN_SOURCE_AUDIT.md](./CAMPAIGN_SOURCE_AUDIT.md), [CAMPAIGN_OPERATION_CONTRACT.md](./CAMPAIGN_OPERATION_CONTRACT.md)

## 1. Purpose

Define the provider-neutral PostgreSQL schema for the GHM Campaign resource used as the durable root container for KBM AI Marketing.

This contract authorizes construction on the GHM construction branch only. It does not authorize production migration, product adapters, HTTP routes, child resources, storage, AI providers, or cutover.

## 2. Canonical relation

```text
ghm.campaign
```

Each row is one business-owned marketing campaign root.

## 3. Canonical columns

| Column | Type | Nullability | Default | Authority |
|---|---|---|---|---|
| `id` | `bigint` identity (`GENERATED BY DEFAULT AS IDENTITY`) | NOT NULL | database | database |
| `business_id` | `bigint` | NOT NULL | none | caller-selected Business; must pass eligibility + membership checks |
| `created_by_account_id` | `bigint` | NOT NULL | none | authenticated Account from `AuthContext.userId` only |
| `title` | `text` | NOT NULL | none | caller (validated) |
| `status` | `text` | NOT NULL | `'draft'` | create default; thereafter governed transitions only |
| `created_at` | `timestamptz` | NOT NULL | `now()` | database |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | database on create; service/repository on update |

Exact physical definition:

```text
id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
business_id bigint NOT NULL
  REFERENCES ghm.business(id) ON DELETE RESTRICT
created_by_account_id bigint NOT NULL
  REFERENCES ghm.account_identity(id) ON DELETE RESTRICT
title text NOT NULL
status text NOT NULL DEFAULT 'draft'
created_at timestamptz NOT NULL DEFAULT now()
updated_at timestamptz NOT NULL DEFAULT now()

CONSTRAINT campaign_title_valid
  CHECK (length(btrim(title)) BETWEEN 1 AND 200)
CONSTRAINT campaign_status_valid
  CHECK (status IN ('draft', 'active', 'archived'))
```

No Supabase UUID, `auth.uid()`, provider identifiers, RLS-specific columns, or speculative KBM child foreign keys are part of this schema.

## 4. Foreign keys

### Owning Business

```text
ghm.campaign.business_id
  -> ghm.business.id
```

Delete behavior: `ON DELETE RESTRICT`.

A campaign cannot exist without a business. Business deletion must not silently cascade-remove campaigns.

### Creator Account

```text
ghm.campaign.created_by_account_id
  -> ghm.account_identity.id
```

Delete behavior: `ON DELETE RESTRICT`.

Creator is provenance only. It is not a substitute for membership authorization.

## 5. Integrity constraints

```text
CONSTRAINT campaign_title_valid
  CHECK (length(btrim(title)) BETWEEN 1 AND 200)

CONSTRAINT campaign_status_valid
  CHECK (status IN ('draft', 'active', 'archived'))
```

Status transition graph is enforced by the operation/service contract (not by additional CHECK constraints beyond the allowed vocabulary).

## 6. Indexes

Required:

```text
campaign_business_created_idx
  ON ghm.campaign (business_id, created_at DESC, id)

campaign_business_status_created_idx
  ON ghm.campaign (business_id, status, created_at DESC, id)

campaign_creator_created_idx
  ON ghm.campaign (created_by_account_id, created_at DESC, id)
```

## 7. Table ownership

```text
OWNER TO ghm_schema_owner
```

Construction and governed cleanup use migrator authority with schema-owner elevation. Runtime operations use `ghm_runtime`.

## 8. Runtime privilege boundary

Follow GHM least-privilege and the **Saved Business–style governed mutation approach**:

1. `GRANT USAGE ON SCHEMA ghm TO ghm_runtime`
2. `GRANT SELECT ON TABLE ghm.campaign TO ghm_runtime`
3. `REVOKE INSERT, UPDATE, DELETE ON TABLE ghm.campaign FROM ghm_runtime` (or equivalent denial of unrestricted DML)
4. Mutations occur only through governed `SECURITY DEFINER` functions owned by `ghm_schema_owner`, with `EXECUTE` granted to `ghm_runtime`
5. Functions must bind `created_by_account_id` from the authenticated account argument supplied by the repository from `AuthContext.userId` — never from an unconstrained caller-chosen owner column write
6. Update functions must not accept or apply changes to `business_id` or `created_by_account_id`
7. No runtime `DELETE` privilege on `ghm.campaign`
8. Sequence `USAGE` only as required for identity generation inside governed create

Exact function signatures are fixed during migration construction to match the operation contract (`create` / `update` / reads via SELECT + membership predicates in repository SQL).

## 9. Ownership immutability

After insert:

- `id` immutable
- `business_id` immutable
- `created_by_account_id` immutable

Runtime must not be able to arbitrarily rewrite ownership columns through table privileges.

## 10. No DELETE

There is no physical delete operation in the first slice.

- no `campaign.delete` operation;
- no `DELETE` grant to `ghm_runtime`;
- archival uses `status = 'archived'`.

Governed cleanup of qualification fixtures uses migrator / schema-owner authority only.

## 11. Business eligibility (schema-adjacent)

Create eligibility predicates evaluated against `ghm.business` and `ghm.business_membership`:

- business row exists;
- `ghm.business.is_active = true`;
- actor has active membership on that business with role `owner` or `administrator`.

Directory verification / approval flags are **not** schema requirements for this slice.

## 12. Fields explicitly excluded

Do not add in this migration/contract:

- objective / audience / offer columns;
- selected concept / script foreign keys;
- presenter / consent / media references;
- generation job references;
- visibility / public disclosure columns;
- soft-delete flags parallel to `archived`;
- provider-specific identifiers.

## 13. Construction boundary

This schema contract freezes design for implementation. It does not by itself create the table. Migration authorship is a subsequent construction step after this freeze.
