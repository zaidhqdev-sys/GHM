## Qualification state

Unit-level construction qualification remains separate from live database qualification.

The transaction boundary has behavior tests proving, without a live database:

- one checked-out client is used;
- `BEGIN` precedes successful work;
- `COMMIT` follows successful work;
- failed work triggers `ROLLBACK`;
- the client is always released;
- authorized transaction work receives the same authenticated `AuthContext` and checked-out client.

Production runtime boundary verification excludes legacy startup schema mutation, implicit administrator bootstrap, fallback JWT secrets, wildcard CORS, and unrestricted generic table endpoints. Supabase Storage provider configuration is intentionally allowed as replaceable infrastructure.

These are unit/boundary proofs. They do not replace live PostgreSQL integration qualification.

This establishes a **development-environment DNS/name-resolution blocker**, not a database credential failure. No database metadata was captured and no database mutation occurred.

The repository capture script is metadata-only and does not read application rows, passwords, tokens, `DATABASE_URL` values, or secrets. It records PostgreSQL/server information, non-system schemas, tables, columns, constraints, foreign keys, indexes, sequences, views, materialized views, routines, triggers, RLS/policies, grants, and estimated row counts. Resulting evidence must be reviewed before committing because definitions/policies/routines can contain sensitive business logic.

## Storage provider decision

Supabase Storage is currently being used as an available/free storage facility. This does **not** make Supabase the GHM backend authority and does **not** block GHM construction.

The required architecture is:

```text
Product → GHM storage boundary → current provider (Supabase Storage for now)

Future:

Product → GHM storage boundary → ZAID-owned storage
```

Do not spend construction effort removing a useful temporary provider merely because it is Supabase. The architectural requirement is provider-neutrality at the GHM boundary so the provider can be swapped later without product rewrites.
